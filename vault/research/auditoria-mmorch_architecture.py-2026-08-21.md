Módulo con buena intención y arquitectura clara, pero presenta 3 bugs reales y 2 problemas estructurales que violan directamente tus principios. El más grave: co_change_pairs puede producir falsos positivos por un bug de parsing, y god_module_candidates relee archivos que ya fueron parseados.

## Findings (sobrevivieron refutacion 6/6 — 1 estructurales, 3 bugs, 1 de principios)

- **god_module_candidates relee archivos que import_graph ya parseó** [media/estructural]: Líneas 47-48 vs 55-56: import_graph ya lee y parsea cada archivo con ast.parse(f.read_text()). Luego god_module_candidates vuelve a leer cada archivo con f.read_text() para contar LOC. Esto viola el ADR 0001-estado-en-memoria-no-releer-disco.md — el contenido ya está en memoria (o al menos el AST), pero se relee del disco. Para un repo con 50 módulos, son 50 lecturas redundantes de disco. Peor: si el archivo cambia entre la primera y segunda lectura (race condition en CI), el LOC contado no corresponde al AST parseado. Fix: hacer que import_graph devuelva también el LOC, o que god_module_candidates reciba los ASTs ya parseados.
- **co_change_pairs cuenta commits vacíos como cambios** [alta/bug]: Líneas 88-96: Cuando un commit toca archivos fuera de mmorch/ (ej: docs/, tests/), el parser agrega un set vacío a commits. El filtro len(c) <= _SWEEP_MAX_FILES no elimina sets vacíos (0 <= 8 es true). Esto infla solo y junto con commits que no tocan ningún archivo relevante, distorsionando los ratios. Un commit que solo toca README.md produce actual = set() que se agrega a commits. Si un commit toca 1 archivo de mmorch/ y 10 de docs, el set tiene 1 elemento, pasa el filtro, y cuenta como co-cambio legítimo cuando en realidad fue un commit de docs con un fix incidental. Fix: filtrar sets vacíos antes del filtro de barrido: commits = [c for c in commits if c and len(c) <= _SWEEP_MAX_FILES]
- **_mutates no detecta mutación vía setattr o globals()[name]** [media/bug]: Líneas 130-141: El regex solo detecta NAME[...] = y NAME.metodo(). Pero Python permite mutar globals sin esas sintaxis: globals()['CONFIG'].update({...}) o setattr(sys.modules[__name__], 'CONFIG', {...}) no son detectados. Un test que haga globals()['SHARED_STATE'].clear() pasa desapercibido. Es un caso borde, pero el módulo se vende como 'chequeo mecánico determinista' — un falso negativo aquí es exactamente el tipo de contaminación que busca prevenir. Fix: añadir detección de globals()[ y setattr( con el nombre como string: globals_call = re.compile(rf"globals\(\)\s*\[\s*['\"]{name}['\"]\s*\]")
- **pollution_candidates no detecta mutación de constantes en otros archivos** [media/bug]: Líneas 143-158: El chequeo de 'global que se muta' solo busca mutaciones en el mismo archivo donde se define la constante. Pero la contaminación entre tests típicamente ocurre cuando un test muta un global de otro módulo: test_a.py importa test_b y hace test_b.SHARED_STATE.append(...). El docstring dice 'constante MAYUSCULA a nivel de modulo que se MUTA en algun test del mismo archivo' — pero la contaminación real entre tests es cuando un test muta el estado de otro. Este chequeo solo atrapa el caso menos común (auto-mutación). Fix: escanear todos los tests para mutaciones de constantes definidas en cualquier test, recolectando todas las constantes de todos los tests primero y luego buscando mutaciones de esas constantes en TODOS los archivos.
- **co_change_pairs usa subprocess en vez de inyectar la dependencia** [baja/principio]: Líneas 76-82: El principio §1 dice 'Seams + injection = testability: el payoff real de una interfaz es insertar un mock'. co_change_pairs ejecuta git log directamente — no hay forma de testear el parsing sin un repo git real. El módulo tiene __main__ self-check, pero este chequeo no puede probarse en aislamiento. Para testear el parsing de commits (la lógica más compleja del módulo), necesitas crear un repo git temporal con commits falsos. Eso es lento y frágil. Con inyección, podrías pasar un git_runner mockeable. Fix: aceptar un parámetro git_runner: Callable[[list[str]], subprocess.CompletedProcess] con default a subprocess.run.
- **_GOD_FANIN_FRAC cuenta __init__.py en el denominador pero no en el numerador** [baja/otro]: Líneas 12, 53: n_mods = len(list((root / 'mmorch').glob('*.py'))) incluye __init__.py (que está en _SKIP y no se cuenta en fan_in). Esto diluye el ratio: si hay 10 módulos + __init__.py, el denominador es 11 pero el máximo fan-in posible es 10. Un módulo importado por 2 de 10 módulos tiene ratio 2/11 = 0.18, superando el umbral de 0.15 cuando en realidad es 2/10 = 0.20 — el error es pequeño pero sistemático. Con _GOD_FANIN_FRAC = 0.15, un módulo importado por 2 de 10 módulos reales (ratio real 0.20) se marca como hub. Fix: excluir _SKIP del denominador: n_mods = len([f for f in (root / 'mmorch').glob('*.py') if f.name not in _SKIP])
