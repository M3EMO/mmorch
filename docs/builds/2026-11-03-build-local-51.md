## 3. Qué falló o quedó incompleto

- **C2 no se hizo.** P62 no tiene respuesta del usuario. Sigue abierta.
- **H5, rama zip.** El script del contenedor lee `PKG-INFO` de `.zip`, pero ningún test cubre esa rama. Los de `.tar.gz` corren el script real con python3.
- **H5, pip y podman reales.** Los tests usan dobles de pip y curl. Solo el test de git clona de verdad.
- **H5, cachés viejas de solo clones.** Una caché de Python hecha antes de H5, sin sdists, sigue siendo acierto. No trae las dependencias de runtime de sus clones. Falta subir la clave de caché.
- **H5, dependencias solo-sdist.** Si una dependencia de runtime solo tiene sdist, pip falla en el paso de build con "No matching distribution". Ese caso sale como `no-instala` (severidad 3), no como sin veredicto. El flujo existente de build ya hacía esto.
- **H5, metadatos viejos.** Un sdist con `PKG-INFO` anterior a Metadata 2.1 no trae `Requires-Dist`. Root lo trata como sin dependencias.
- **L14, `src/lib.rs` queda fuera de mi lista.** `cache_de_con_error` da el error de lectura. `cache_de` lo oculta y lo mantiene para `src/lib.rs:480`. Ese llamador debe pasar a `cache_de_con_error(...)?`. Ese cambio es de una línea.
- **Punto 7, solo la descarga.** `contenedor::ejecutar` y `entrega.rs` siguen leyendo la salida sin tope. Están fuera de mi lista.
- **M22.** Un `pyproject.toml` que es un symlink, pasa el tope o no es UTF-8 se trata como ausente. Un clon así con dependencias dinámicas no corta.
