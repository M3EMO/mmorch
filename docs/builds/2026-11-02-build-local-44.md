## 3. Qué falló o quedó incompleto

- **Tope lleno con `JuezProveedor`.** No hay test de integración con el tope en 0. `ejecutar` exige la clave del entorno antes de reservar el tope. Sin clave, el error sería `SinClave` y no probaría el tope. Un test con clave falsa rompe la regla de no exportar claves.
- **Cobertura del tope.** El test `juez_reintento_con_error_del_modelo_deja_faltante` cubre el caso en el trait. El reintento usa el mismo `consultar` que la primera llamada, y ese camino hace el chequeo previo de tope.
- **Causa del reintento fallido.** Si el reintento da error, sale truncado o no se parsea, Root no guarda la causa. Solo deja el motivo "el juez no respondió tras un reintento".
- **Tests viejos ajustados.** Cada respuesta que omite ítems ahora pide un segundo envío. Se ajustaron `juez_prompt_con_spec_chica_se_envia`, `juez_modelo_recibe_el_prompt_construido`, `juez_id_repetido_no_cuenta_ninguna_copia`, y en `mod.rs` cuatro tests del oráculo (llamadas 1 a 2, costo 0,35 a 0,6, motivos).
- **Texto de descarte.** "no tiene dimensión conocida" pasó a "no está entre los pedidos".
- **`ResultadoJuez` no cambió.** `docs/interfaces.md` no necesita regeneración.

## 4. Preguntas para el planner

1. **Gate que falla dos veces.** Un id cuya evidencia falla el gate también en el reintento queda con "el juez no respondió tras un reintento". El motivo "la evidencia no pasó el gate" ya no aparece en `faltantes`. Decisión: seguir el texto del brief. ¿Debe el gate persistente conservar su motivo?
2. **Nivel inválido.** Un nivel mal tipado ("alto") o fuera de 0 a 3 no rompe el contrato y no se reintenta. Queda con "el juez no dio nivel". Decisión: el brief solo nombra falta, repetición y ausencia de nivel. ¿Debe contar como roto?
3. **Id repetido.** Ninguna de sus copias cuenta, y el id va al reintento. Antes valía la primera. Decisión: el brief dice que la repetición rompe el contrato.
4. **Nivel y `sin_evidencia` juntos.** Gana el nivel. Decisión: el nivel con evidencia pasa por el gate como siempre.
5. **Hallazgos del reintento.** Root los ignora. Decisión: el reintento pide solo ítems.
6. **Costo.** Cada juicio con ítems omitidos o sin gate cuesta dos llamadas. El brief ya lo prevé. La calibración mide cuántos juicios reintentan.
7. **Sección REINTENTO.** Va antes de EXTRACTOS. Decisión: el modelo la lee junto a los ids. ¿Conviene al final del mensaje?
8. **Test de tope con clave falsa.** ¿Se acepta una clave falsa solo en un test de integración? Decisión: no se escribió.
