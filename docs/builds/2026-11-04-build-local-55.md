## 3. Qué falló o quedó incompleto

- **Punto 7, medición real.** `claude --version` corre en `root-builder:1` con `--cap-drop=all`, `no-new-privileges`, `--pids-limit=4096` y `--memory=8g` juntas. La prueba usó `--network none` y no tuvo credenciales. No prueba una corrida real con red. Ninguna opción quedó afuera.
- **Punto 2, filtros.** Un `-c` no apaga un `filter.*` definido en `.git/config`. `comando_git` apaga fsmonitor, hooks y `core.attributesFile`. El `.gitattributes` del repo sigue activo. El punto 1 cierra el riesgo: `git add` y `git status` ya no corren sobre el repo del builder. `commit_de` y el evaluador solo corren `rev-parse` y copian sin `.git`.
- **Punto 1, historial.** El evaluador recibe `<corrida>/final`, con un solo commit "r00t corre: estado final". El historial de commits del builder no pasa a ese repo. El repo del builder queda en `<corrida>/repo`.
- **Punto 3, `src/oracle/contenedor.rs`.** El oráculo trata solo el código 125 como infraestructura. No lo toqué: está fuera de mi lista. Va al planner.
- **Punto 5, pruebas.** El mapeo de un corte real a `ErrorCorre::Cortado` dentro de `lanzar` no tiene test, porque exige podman. Los tests cubren `correr_proceso` y `correr` con un builder falso.
- **Punto 5, pipe retenida.** Si un proceso nieto retiene la pipe, el stdout parcial se pierde tras 2 s de espera. El evento sale con costo 0 y `costo_estimado = true`.
- **Punto 5, `Config::cargar`.** Si falla al registrar el corte, el error sale como `Uso` y el evento de costo no se escribe. El transcript sí queda guardado.
- **`docs/interfaces.md`.** No cambió: no hay campos nuevos en esquemas. `extra.costo_estimado` y `extra.precio_supuesto` son claves nuevas de `extra`.
